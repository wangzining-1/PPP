# 转换与重建指南

本文是格式适配与像素辅助工具的补充。机制图以 SKILL.md 的结构重建流程为准；不能因要求外观一致改成像素文字。

## 输入适配

按文件内容检测格式，不只看后缀。`scripts/pixel_vectors.py` 依赖 Pillow，可处理当前安装解码器支持的 PNG/JPEG/BMP/TIFF/GIF/WebP 等。运行 `--formats` 获取本机实际支持列表。HEIC/AVIF、PSD、EXR、RAW 等取决于解码器与图层规则，不能宣称全部原生支持。未支持时检测可用的本地专用解码器，转为无损 PNG/TIFF 并记录命令、色彩变换与所选图层；无法解码就报告具体格式和缺少组件，不改后缀冒充转换。

EXIF 方向先归一化。带 ICC 的图像经配置转换为 sRGB；无配置 RGB 假定为 sRGB并记录。CMYK 缺少 ICC 时要求明确颜色解释后再转换。HDR、浮点和高于 8 位的图像需明确色调映射/量化选择，8 位工具不能声称保留其原始数值。保真承诺仅针对明确记录的归一化 8 位 RGBA。透明度为零处隐藏的 RGB 不影响外观，不作为可见像素误差。

GIF/TIFF/APNG 多帧/多页必须明确索引（从 0 开始），不能悄悄只取第一帧。动画不能由单张幻灯片完整表达。PDF/SVG 若含原生矢量则优先提取，不先栅格化。已有 PPT 的图片须核对裁剪、旋转、透明效果；当前生成脚本创建新文件，向已有 PPT 放置由代理另行处理并验证其他页面没有变化。

## 像素保真工具

使用工作区依赖工具获得 Python、Node 和包路径；无该工具时检测实际运行环境。Python 需要 Pillow，PPT 导出脚本需要 `@oai/artifact-tool`。不要硬编码某台机器的用户路径或修改捆绑依赖。以下命令中的路径替换为实际绝对路径：

```text
python <skill>/scripts/pixel_vectors.py input.png --out-dir <build>/vectors
python <skill>/scripts/pixel_vectors.py input.tiff --frame 1 --out-dir <build>/vectors
node <skill>/scripts/vectors_to_pptx.mjs <build>/vectors/geometry.json <build>/candidate.pptx
```

设置 `RUNTIME_NODE_MODULES` 为实际依赖包根目录供 Node 解析。输出目录必须为新目录，PPTX 路径必须不存在。

像素脚本不缩放、不减色，仅把水平同色 RGBA 游程及相邻行完全相同的游程合并。每个可见像素恰好覆盖一次，避免半透明区域叠加。透明区域不绘制。输出 `vector.svg`、`geometry.json`，后者记录归一化信息及整数像素边界。几何值可重建采样颜色，不等于已经验证 PPT 渲染零误差。

默认 `--max-shapes 20000`；超出时不写出结果，也不自动转为近似模式。经用户选定规模后可增加预算或按区域分文件，说明跨文件编辑影响。不得把 1200 万像素照片未经估算直接写成数百万形状。保留抗锯齿需要保留其颜色/Alpha，不要把半透明边缘阈值化。

PPT 脚本把每个色块写为无描边的原生矩形，画布保持原图比例，最长边为 960 CSS 像素。画布背景为白色，可编辑；图形本身保留 Alpha。坐标从统一像素边界计算，不逐个累加舍入。输出是待验证草稿。

若有 Presentations 技能，读取其当前实现与验证指南，遵循运行环境和 finalizer 流程；用户明确要求矢量描摹，使用原生图形符合该任务。最终要验证导出的 PPTX，而非只检查内存预览。没有该技能时也执行下述包结构与渲染验证。

## 结构重建

先拆分背景、主体、文字、连线、遮挡关系。记录每个元素的边界框、填充/描边、透明度、层级。以原图坐标建立统一映射，保留比例。

- 几何图形用原生矩形、椭圆、连接符；曲线用原生自由曲线/自定义 DrawingML 路径。只提取外轮廓会填死孔洞，须保留内环与填充规则。
- 多色区域按覆盖顺序重建，拟合误差以源图像素计。无用户阈值时用 0.5 像素边界误差作为迭代目标并记录，不把它当成“完全一致”。细线、箭头和关键标记独立检查。
- OCR 只是候选文本。逐项核对字符、单位、上下标与换行。字体不可用时说明差异；若优先外观可转字形轮廓，但需说明不能再编辑为文本。模糊字不猜写。
- 科学图表保留坐标轴、刻度、曲线、图例和标记。仅在得到源数据或明确可靠数据时创建数据图表；截图数字化结果标为估计，不编造精确数据。
- 渐变、纹理、阴影需通过可编辑填充或分层路径拟合。照片的少量平滑路径只能近似，不把原图嵌入作为“纯矢量”的完成依据。

## 验证

1. 用 ZIP/XML 检查目标绘图区：应有 `p:sp`（或用户要求的原生图表/文本），不存在承担原图内容的 `p:pic`、`a:blip`、外部图像关系或 SVG `<image>`。与任务无关的原有图片不应删除。
2. 逐个验证颜色、Alpha、边界坐标、形状数与几何 JSON 一致；透明区域不得重复覆盖。PPT 包完整性、渲染与可编辑性分别报告。
3. 使用可用渲染器从最终 PPTX 导出 PNG，映射回原图尺寸，注明缩放及背景。计算 RGB 平均绝对误差、最大误差、差异像素比例；文字和细线区域单独检查，不能只用全图平均掩盖缺字。像素相等无需容差；允许近似时报告实际指标及阈值来源。
4. 查看原图、渲染图、50% 叠加和差异图。PPT 的坐标精度、Alpha 精度、抗锯齿和字体会产生残差。不能把内部色块重建通过冒充 PowerPoint 渲染通过。
5. 缺少实际 PPT 渲染器时，交付状态为“已生成/已检查对象结构，PPT视觉未验证”。若能操作 PowerPoint，再检查打开文件、选中形状、改变颜色/节点及撤销；只在实际完成后声明该检查通过。
